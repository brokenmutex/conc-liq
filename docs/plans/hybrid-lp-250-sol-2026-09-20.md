## Objective and finish line

Determine whether a cost-aware policy that separates range placement from
inventory trading is a credible $250 paper candidate. Test fixed and adaptive
widths; do not assume either wins. Optimize independently valued net alpha
against matched passive inventory while reporting absolute net profit and risk.
Returning **no viable candidate** is a valid, useful result.

Sol's deliverable is tested research/paper code, a reproducible comparison,
and an activation-ready but inactive prospective paper package, or a documented
rejection/data blocker. It is **not** a funded live strategy or a promise of profit.
Prepare a conditional $250 live-canary checklist, not live activation.

Execute phases in order. Update the checklist and evidence links in this file
after each phase. Stop expanding the investigation when the stated acceptance
conditions are met; full reverse engineering of the competitor is not required.

## Phase 2 — opt-in hybrid decision engine

Prefer a separate `src/research/hybrid-lp.ts` with reusable pure planner helpers,
rather than changing the semantics of the existing inventory-only arm. Proposed
new paths are suggestions, not a requirement to duplicate existing infrastructure.
Use verified token metadata, `bigint` V3 math and exact tick-spacing alignment.

At every eligible checkpoint compare these distinct choices:

1. Keep the current position and idle inventory.
2. Redeploy current inventory without a swap, including asymmetric ranges.
3. Redeploy with a bounded inventory-adjustment swap in either direction.

Also retain the active strategy contract's managed alternatives: wait while
one-sided, place a one-sided residual range, widen/reduce deployment, and exit.
Reuse existing primitives where possible. A range need not contain spot to be a
valid residual candidate; explicitly label its currently inactive fee forecast.
One managed NFT plus idle tokens is enough for the first $250 engine. Do not copy
the competitor's multi-NFT concurrency; supporting that is a separate expansion.

- [x] Enumerate a bounded, manifest-pinned grid of widths, offsets and deployment
  fractions. Initial full spans: 1, 2, 4, 8, 16, 32 spacings; fixed-width arms each
  pin one span. Never confuse full spans with existing half-width parameters.
- [x] Define the bounded swap search precisely: feasible direction/input candidates,
  raw-unit rounding, input caps and liquidity minimums. Include zero swap. Prefer
  the smallest input among economically equivalent candidates; do not claim a
  global optimum from a finite grid or force a 50/50 wallet reset.
- [x] Compare complete post-action portfolios, including all idle/residual tokens,
  using the same causal forecast and terminal valuation convention as keeping.
- [x] Define incremental benefit as move value minus keep value minus incremental
  action costs not already charged in the forecast. Require strict `benefit >
  buffer`; preserve the existing 50%-of-cost / 25%-of-forecast-fees buffer convention
  unless a separately preregistered sensitivity arm changes it.
- [x] Include approvals when necessary, withdraw/collect, swap fee and execution
  shortfall, mint, gas, adverse-selection allowance, and reserved exit. Explicitly
  document which costs are already embedded in quotes to prevent double counting.
- [x] Preserve the 60-minute causal lookback, ten-minute forecast horizon,
  30-second decision interval, ten-minute cooldown, and two confirmations as
  initial research defaults. A lookback is not a session duration. Freeze candidate
  identity, input/direction, minima and TTL; recheck feasibility and economics at fill.
- [x] Persist reason-coded decisions and rejection counts, not just executed moves.
  Missing inputs reject actions without inventing prices, inventory or costs.

Acceptance: absent a strictly better feasible action, the engine keeps/waits.
No free inventory, hidden external funding, future samples, unpriced idle assets,
or forced swap is possible. Legacy arms/configs retain their existing behavior.
