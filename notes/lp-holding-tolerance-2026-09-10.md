# Bounded infrastructure pauses — 10 September 2026

The approved change uses **30 blocks**, with 64 confirmations on each participating node, a 60-second transient chain incident budget and a 30-second risk-proof retry budget. It separates retaining an existing paper LP from permission to start or simulate a transaction. It does not change sizing, range width, inventory threshold or the ±5% independent reference band.

## Implementation

- The RPC monitor uses its configured soft block-lag bound for anchor adjustment; its default is now 30. At lag 30 the anchor can move back enough to retain 64 confirmations on every participating head. At 31 it uses the reference-derived anchor and reports degraded health. Every hash still requires a real read. Time lag, latency, syncing and hard limits continue to apply independently.
- The continuous paper policy explicitly opts into `bounded_infrastructure_v1`. Old policies retain their shape and hash. Holding control runs under a row lock before boundary RPCs or checkpoint waits, checks the full funding/evidence ancestry, and saves the first failure times in `state.holding`. Later ticks inspect every new raw health sample, including incidents that occurred between paper ticks.
- Missing quorum responses, brief syncing and soft lag can pause observation. Actual conflicting hashes, chain identity errors, regressed heads, the existing hard monitor reasons and substantive reference/token safety failures latch an exit requirement. The hard 107-block incident in session 40 remains hard. Historical accounting/canonicality revocation still invalidates the result immediately.
- Raw chain recovery stops its incident clock; monitor recovery hysteresis alone does not exhaust the 60-second budget. Bulk RPC restrictions remain active during hysteresis. Entry and transaction preflight retain the full five-minute readiness proof. A recovered holding decision can mark a verified position without repeatedly requesting exit because an older health sample remains in that entry window.
- A chain pause also suspends the normal risk producer. The risk retry budget starts when bulk RPC becomes available again. A validation-age failure requests a real hash validation; other missing/failed metadata requests one bounded snapshot refresh. Requests are limited to one per incident, 256 RPC calls, no transport retries, five-second network timeouts and a 20-second admission deadline. A request already in flight can finish after that deadline; it cannot initiate further calls. The next tick evaluates the resulting database proof using its SQL clock. No old validation timestamp is relabelled fresh, and a newer failed completion is not skipped.
- Accounting remains at its last verified checkpoint while paused. `state.holding` exposes the pause, evidence, retained incident timestamps, bounded transition history and any latched exit requirement; the existing source timestamp exposes mark age. On recovery, select the latest checkpoint, then account for the **whole interval** from the previous accepted checkpoint using indexed swaps, Mint/Burn continuity and fresh boundary proofs. Record the resumed interval. Missing continuity or an excessive gap invalidates instead of inventing fees or intermediate trades. The normal 900-second maximum accounting gap remains.
- Expired or hard exit requirements persist through recovery. A position can remain physically represented as open during an RPC pause, with the exit requirement latched in `state.holding.exitReasons`; ordinary exit intent/fill processing resumes only when evidence and execution gates permit. This is a paper state machine, not a guarantee of successful live liquidation during an outage.
